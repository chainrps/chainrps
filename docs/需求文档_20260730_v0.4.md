## 一、核心决策总览

| 维度 | 决策 | 依据 |
|---|---|---|
| 默认结算代币 | **USDC**（Polygon 原生 USDC），POL/USDT 可选 | 价格稳定、合规友好、支持 EIP-2612 Permit |
| Gasless 范围 | **全流程 Gasless**（createMatch / joinMatch / commit / reveal / handleDraw / claimTimeout） | 借鉴 Marketplace L3 方案，玩家零 POL 也能玩 |
| Gas 成本归属 | **三档阶梯**：小额平台全包 / 中额从胜者奖金扣回 / 大额不允许 Gasless | 平衡获客成本与平台风险 |
| Relayer 部署 | **后端内置 relayer**（沿用现有 relayer_service.py） | 部署简单、运维集中 |
| 签名次数 | **A/B 双模式可选**：默认 A（每局 1 次签名）/ 用户可开启 B（7 天零签名） | 兼顾安全与体验 |
| 方案B | **补全逻辑真正可用**（relayer 持授权可代提交全部操作） | 已写合约但实际不可用，需补全 |

## 二、测试验证结论（2026-07-30）

### 2.1 测试范围
- 签名一致性测试（Python eth_account + EIP-712 签名/恢复）
- 合约编译测试（py-solc-x，Forge 未安装）
- 配置一致性静态检查（前端 config.js vs 后端 .env.example vs 合约常量）

### 2.2 测试结果：30 PASS / 1 FAIL

#### ✅ 签名逻辑验证（核心关注点 — 全部通过）

| 测试项 | 结果 |
|---|---|
| EIP-712 域 version 前后端一致（v1.2.0） | ✅ |
| Commit 类型哈希字段名/类型前后端一致 | ✅ |
| Reveal 类型哈希字段名/类型前后端一致 | ✅ |
| commit 哈希计算 keccak(abi.encodePacked) 正确 | ✅ |
| **Commit 签名 ecrecover 恢复正确地址** | ✅ |
| **Reveal 签名 ecrecover 恢复正确地址** | ✅ |
| 不同 salt 产生不同 commit（防作弊有效） | ✅ |
| 合约 nonce 校验逻辑存在 | ✅ |

**关键结论**：签名逻辑本身正确，前两天修改的签名功能有效。用户感知的"2-3 次签名"是当前设计的正常行为（commit 签名 + reveal 签名 + 链上交易），**非 bug**。

- ChainRPS.sol 在不启用 viaIR 时编译失败（Stack too deep）
- `compile.py` 已配置 `viaIR: True`（正常）
- **`foundry.toml` 缺少 `via_ir = true`**（用 `forge build` 会失败）→ 对应需求 F1-12

#### ⚠️ 配置问题（6 个）

| # | 问题 | 严重度 | 对应需求 |

#### ✅ 已确认正常的项

### 3.2 一期 P0 - 安全

| ID | 需求 | 实现要点 |
|---|---|---|
| **S1-01** | EIP-712 域分隔符链 ID 绑定 | 切链后强制刷新 `_chainId` 与 `_domainSeparator`，防跨链重放 |
| **S1-02** | Relayer 私钥隔离 | 私钥仅环境变量加载，不入库、不上日志、不传前端 |
| **S1-03** | 签名加 deadline 字段 | 所有 `*WithSig` 函数签名结构体包含 `deadline`，过期签名拒绝 |
| **S1-04** | 合约 pause 应急 | relayer 被攻破时 owner 一键 `pause()` 止损（合约已支持，补操作 Runbook） |
| **S1-05** | Relayer 白名单 | 合约增加 `relayerWhitelist`，只有白名单 relayer 可调 `*WithSig`，防 griefing |

### 3.3 一期 P0 - 性能

| ID | 需求 | 实现要点 |
