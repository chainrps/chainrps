## 1. 环境准备

### 1.1 依赖安装

```bash
# 进入项目目录
cd D:\Git\github\chainrps\chainrps

# 安装 Python 依赖
pip install -e .

# 安装 Foundry（合约编译部署工具）
# 参考：https://book.getfoundry.sh/getting-started/installation
```

### 1.2 工具准备

| 工具 | 版本要求 | 用途 |
|------|----------|------|
| Python | >= 3.11 | 后端服务运行 |
| Redis | >= 7.0 | 匹配队列和缓存 |
| MetaMask | 最新版本 | Web3 钱包 |
| Foundry | 最新版本 | 合约编译部署 |

### 1.3 Redis 服务启动

```bash
# Windows (使用 WSL 或 Redis Windows 版本)
redis-server

# 验证连接
redis-cli ping
# 返回 PONG 表示正常
```

## 2. 合约部署

### 2.1 编译合约

```bash
# 进入合约目录
cd contracts

# 编译合约
forge build

# 验证编译结果
ls out/
# 应包含 chainrps.sol/chainrps.json
```

### 2.2 部署到测试网

#### 方式一：使用 Foundry 部署

```bash
# 创建 .env 文件
cat > .env << EOF
RPC_URL=https://rpc-amoy.polygon.technology/
PRIVATE_KEY=your_private_key_here
EOF

# 部署合约
forge create --rpc-url \$RPC_URL --private-key \$PRIVATE_KEY src/chainrps.sol:chainrps

# 部署成功后会输出合约地址
# Example: Deployed to: 0x1234567890abcdef1234567890abcdef12345678
```

#### 方式二：使用部署脚本

```bash
# 使用项目提供的部署脚本
python contracts/scripts/deploy.py

# 按照提示输入私钥，获取合约地址
```

### 2.3 记录合约信息

部署成功后，记录以下信息：
- **合约地址**: `0xYourContractAddress`
- **部署区块号**: `12345678`
- **链 ID**: `80002` (Polygon Amoy 测试网)

## 3. 后端服务配置与启动

### 3.1 配置文件设置

创建 `.env` 文件：

```bash
cd D:\Git\github\chainrps\chainrps
notepad .env
```

粘贴以下内容并修改：

```ini
# 服务配置
HOST=0.0.0.0
PORT=8000

# Redis 配置
REDIS_URL=redis://localhost:6379/0

# 合约配置
CONTRACT_ADDRESS=0xYourContractAddress
RPC_URL=https://rpc-amoy.polygon.technology/
CHAIN_ID=80002

# 超时配置（秒）
COMMIT_TIMEOUT=66
REVEAL_TIMEOUT=88

# WebSocket 配置
WS_HEARTBEAT_INTERVAL=30

# Redis Key 前缀
MATCH_QUEUE_PREFIX=rps:match:
GAME_CACHE_PREFIX=rps:game:
WS_PREFIX=rps:ws:
```

### 3.2 启动后端服务

```bash
# 确保 Redis 已启动
redis-server

# 启动后端服务
python main.py
```

**预期输出：**

```
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
✅ Redis 连接成功
🚀 ChainRPS 后端服务启动
📡 API: http://0.0.0.0:8000
📡 API 文档: http://0.0.0.0:8000/docs
🔌 WebSocket: ws://0.0.0.0:8000/ws/{player_address}
```

### 3.3 验证后端服务


## 5. 完整游戏流程测试

### 5.1 测试前准备

1. **安装 MetaMask 浏览器扩展**
2. **切换到 Polygon Amoy 测试网**
3. **获取测试代币**（从 Polygon 水龙头）

### 5.2 测试步骤

#### 步骤 1：连接钱包

```
1. 打开 http://localhost:8000
2. 点击「连接钱包」按钮
3. 在 MetaMask 弹窗中授权连接
4. 确认钱包地址显示在右上角
```

#### 步骤 2：准备游戏

```
1. 选择代币：点击 USDC 或 USDT
2. 选择下注金额：点击快速金额按钮或手动输入
3. 确认余额显示正确
```

#### 步骤 3：快速匹配模式（模式 A）

```
1. 确保在「快速匹配」模式
2. 点击「寻找对手」按钮
3. 授权代币花费（首次需要）
4. 等待匹配（约 1-30 秒）
5. 匹配成功后进入游戏界面
```

#### 步骤 4：私密对局模式（模式 B）

```
1. 切换到「私密纯净」模式
2. 点击「创建/加入私密对局」
3. 创建对局：自动生成对局 ID，复制给对手
4. 加入对局：输入对手分享的对局 ID
```

#### 步骤 5：游戏流程

```
┌─────────────────────────────────────────────────────────────┐
│                    游戏阶段流程                              │
├─────────────────────────────────────────────────────────────┤
│  1. 提交阶段（Commit）                                       │
│     └─ 选择石头/剪刀/布，系统自动生成哈希提交到链上             │
│                                                             │
│  2. 揭晓阶段（Reveal）                                        │
│     └─ 双方提交后，点击「揭晓出拳」公布选择                    │
│                                                             │
│  3. 结算阶段（Settle）                                        │
│     └─ 智能合约自动判定胜负，奖金自动发放                      │
└─────────────────────────────────────────────────────────────┘
```

#### 步骤 6：查看结果

```
1. 游戏结束后显示胜负结果
2. 查看历史记录：点击「历史记录」标签
3. 查看统计数据：点击「我的统计」标签
```

## 6. 常见问题排查

### 6.1 合约部署失败

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `Insufficient balance` | 测试网余额不足 | 从水龙头获取测试代币 |
| `Invalid private key` | 私钥格式错误 | 检查私钥是否为 64 位十六进制 |
| `Connection timeout` | RPC 连接失败 | 检查网络或更换 RPC 节点 |

### 6.2 后端服务启动失败

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `Redis connection failed` | Redis 未启动或配置错误 | 确保 Redis 服务运行，检查 REDIS_URL |
| `Port 8000 in use` | 端口被占用 | 更换 PORT 或停止占用进程 |
| `Contract not found` | 合约地址配置错误 | 检查 CONTRACT_ADDRESS |

### 6.3 前端页面问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 样式不显示 | 静态文件路径错误 | 检查 CSS/JS 文件路径配置 |
| 钱包连接失败 | 未安装 MetaMask | 安装 MetaMask 并切换到正确网络 |
| 匹配无响应 | 后端或 Redis 未启动 | 确保后端和 Redis 服务运行 |

### 6.4 游戏流程问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 授权失败 | 代币余额不足或用户拒绝 | 确保有足够代币，重新授权 |
| 提交失败 | Gas 费用不足 | 增加 Gas 费用或等待网络拥堵缓解 |
| 揭晓超时 | 对手未在时间内揭晓 | 可索赔超时胜利 |

## 7. 管理员功能规划

### 7.1 功能架构

```
┌─────────────────────────────────────────────────────────────┐
│                    管理员后台管理                            │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │ 合约管理    │  │ 配置管理    │  │ 用户管理    │         │
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘         │
└─────────┼────────────────┼────────────────┼─────────────────┘
          │                │                │
          ▼                ▼                ▼
┌─────────────────────────────────────────────────────────────┐
│                    权限验证层                                │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ 钱包地址白名单验证 → 权限分级 → 操作审计日志         │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 权限分级设计

| 权限级别 | 钱包地址条件 | 可执行操作 |
|----------|-------------|-----------|
| 超级管理员 | 白名单地址 | 全部操作，包括权限管理 |
| 部署员 | 白名单地址 | 合约部署、升级、配置修改 |
| 查看员 | 白名单地址 | 仅查看，不可修改 |

### 7.3 合约管理面板功能

| 功能 | 说明 | API 端点 |
|------|------|---------|
| 合约列表 | 查看已部署合约版本 | `GET /api/admin/contracts` |
| 合约部署 | 上传源码并部署 | `POST /api/admin/contracts/deploy` |
| 合约升级 | 升级现有合约 | `POST /api/admin/contracts/{id}/upgrade` |
| ABI 管理 | 查看/更新 ABI | `GET/POST /api/admin/contracts/{id}/abi` |
| 合约验证 | 验证合约源代码 | `POST /api/admin/contracts/{id}/verify` |

### 7.4 配置管理界面功能

| 功能 | 说明 | API 端点 |
|------|------|---------|
| 配置查看 | 查看所有配置项 | `GET /api/admin/config` |
| 配置更新 | 更新单个配置 | `PUT /api/admin/config/{key}` |
| 配置批量更新 | 批量更新配置 | `POST /api/admin/config/batch` |
| 配置重置 | 重置为默认值 | `POST /api/admin/config/reset` |
| 配置历史 | 查看配置变更历史 | `GET /api/admin/config/history` |

### 7.5 用户配置功能规划

| 功能 | 说明 | API 端点 |
|------|------|---------|
| 个人资料 | 查看/修改个人信息 | `GET/PUT /api/user/profile` |
| 游戏偏好 | 设置游戏相关偏好 | `GET/PUT /api/user/preferences` |
| 主题设置 | 切换深色/浅色主题 | `POST /api/user/theme` |
| 通知设置 | 配置通知偏好 | `GET/PUT /api/user/notifications` |

### 7.6 数据库设计建议

#### 用户配置表
| 字段 | 类型 | 说明 |
|------|------|------|
| user_address | VARCHAR(42) | 用户钱包地址（主键） |
| preferences | JSON | 用户偏好配置 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

#### 系统配置表
| 字段 | 类型 | 说明 |
|------|------|------|
| config_key | VARCHAR(100) | 配置键（主键） |
| config_value | TEXT | 配置值 |
| category | VARCHAR(50) | 配置分类 |
| description | TEXT | 配置描述 |
| updated_by | VARCHAR(42) | 更新者地址 |
| updated_at | DATETIME | 更新时间 |

#### 合约记录表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 自增主键 |
| name | VARCHAR(100) | 合约名称 |
| address | VARCHAR(42) | 合约地址 |
| abi | TEXT | ABI JSON |
| version | VARCHAR(20) | 版本号 |
| deployed_by | VARCHAR(42) | 部署者地址 |
| deployed_at | DATETIME | 部署时间 |
| status | VARCHAR(20) | 状态 |

### 7.7 安全考虑

1. **权限隔离**：管理员操作必须验证钱包签名
2. **操作审计**：记录所有管理员操作日志
3. **配置验证**：更新配置前验证格式和范围
4. **敏感信息保护**：不返回敏感配置值
5. **HTTPS 强制**：生产环境强制使用 HTTPS
